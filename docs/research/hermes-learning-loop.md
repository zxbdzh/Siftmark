## 改造前实现核实

- `src/capture-agent/capture-agent.ts` 已处理允许、拒绝、调整、撤销，但普通反馈的软偏好写入不受睡眠回顾开关约束。
- `learning-repository.ts` 已能将回顾记忆与来源标记原子提交；`sleep-review.ts` 已有批量、冷却及回顾状态，但手动回顾允许单条证据成为记忆。
- `smart-planner.ts` 已将偏好用于候选目录和模型上下文；现有实现会发送学习摘要，缺少独立的学习记录上传授权。
- `CaptureLearningSection.tsx` 已显示及删除睡眠记忆；缺少本地学习总开关、纠错、暂停后阻止积累和主动本地方案。
- 当前实际管理器是 `entrypoints/manager/App.tsx` 的书签树。旧 `ManagerLayout` 不是这次实机入口，不能只改旧组件声称完成。

## 增量边界

闭环：授权观察 → 短期结构化证据 → 重复明确反馈归纳 → 应用后续分类/检索/关联/整批预览 → 用户反馈修正。

书签 ID 和目录 ID 仅为引用。每次使用前读取浏览器原生书签验证存在及当前目录，不从学习记录重建书签。普通反馈至少来自两个不同书签才形成长期经验；撤销、拒绝和用户纠错优先；过期或失效目录不参与策略。

主动性仅包含有界本地检查、生成持久待确认方案和复盘。复用既有 CaptureSession、本地执行器与撤销；不在后台自动移动或删除书签。学习关闭、清空或删除后，不得由迟到写入及旧来源重新积累。

不包含：模型训练、任意脚本技能、全网浏览监控、默认上传学习数据、自动删除、自动批量移动、另一套书签事实库。

## 本次实现与验收结果

已接入实际管理器、收藏规划器、整批整理的本地计划调整及设置页。经验按域名或检索词匹配“优先/避开目录”，保留来源、置信度、更新时间和纠正状态；任务上下文继续使用原有会话存储。

| 行为 | 验证结果 |
| --- | --- |
| 分类反馈形成经验 | 在临时原生书签副本中，将两个不同书签调整到同一目录，生成两条证据和一条经验 |
| 主动方案确认与撤销 | 本地复盘生成三个待确认方案；确认前原生位置不变，确认一条后移动，撤销后恢复原位置 |
| 纠错与删除 | 将经验纠正到另一目录后，旧方案撤回，新方案采用纠正目录；删除该经验后再次复盘生成零个分类方案，新增检索反馈也未使旧经验复活 |
| 检索反馈改变下一次排序 | 对同一检索选择两个不同书签后，下一次检索中对应目录由第二位升到第一位；实机同时修复新增状态提示导致的树区域顶部空白 |
| 暂停与恢复 | 暂停后普通分类调整及撤销继续工作，证据数保持不变；重载扩展后经验和方案保留。执行中断的已执行、待确认及冲突失败恢复由自动测试覆盖 |

最终运行 `pnpm typecheck && pnpm lint && pnpm test && pnpm build` 全部通过：114 个测试文件，485 条测试。随后运行 `pnpm zip` 生成 Chromium 安装包，并更新、重载浏览器已加载的扩展目录。

自动测试另覆盖重复反馈门槛、用户纠正优先、明确固定规则优先、冲突及过期失效、暂停、清空后不复活、无效目录、不可信输入、主动方案数量及冷却限制、幂等执行和整理分类树边界。

验收完成后已删除仅含测试节点的临时目录及相关证据、会话、索引和操作日志，恢复原设置。对其余原生书签的 ID、父级、标题、URL、顺序及既有学习记录比对一致；本地学习恢复为默认关闭。
