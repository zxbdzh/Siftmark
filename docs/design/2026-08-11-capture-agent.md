# 收藏 Agent 设计

## 目标

Siftmark 的核心任务是让收藏动作保持和浏览器一样快，同时把需要判断的整理工作交给 AI。用户不应先打开扩展、选择目录或等待模型，原生书签必须先成为事实。

## 产品约束

- 主入口：原生 `Ctrl+D`/星标。
- 等价入口：`Ctrl+Shift+S`、当前页右键、链接右键。
- 不提供常驻悬浮按钮，也不把 Popup 作为手动保存表单。
- 默认接管原生收藏并自动归类。
- 只有风险方案打断用户；安全方案自动执行。
- 审批只有“允许”与“拒绝”，对话用于调整方案，不引入版本选择。
- 模型只提出方案，本地代码拥有全部写入权限。

## 核心不变量

1. 先保存：任何模型、网络、Schema 或页面采集失败都不能删除新建书签。
2. 本地执行：模型响应不能携带 URL 修改、脚本、权限或任意 Chrome API 操作。
3. 执行前校验：来源书签和目标目录必须仍与快照一致。
4. 风险收窄：只有无风险且可执行的方案才能自动执行。
5. 可撤销：同一方案的目录创建、移动、改名、元数据和重复合并属于一个有序批次。
6. 学习分级：普通决策是弱偏好，只有明确未来意图才能成为固定规则。
7. 数据最小化：不向模型发送查询参数、完整书签库、私密备注或无界正文。

## 状态模型

```text
analyzing -> ready -> applied(auto)
                    \
                     -> pending -> adjusting -> pending
                                -> applied(allowed)
                                -> rejected

analyzing/pending -> failed -> retry -> analyzing
applied -> adjusting -> pending
applied -> undone
pending/failed -> expired
```

`CaptureAgent.begin` 创建会话并规划；`CaptureAgent.respond` 是允许、拒绝、消息、重试和撤销的唯一入口。UI 不组合底层写操作。

## 方案与风险

结构化方案包含：

- 已有目标目录路径与待创建目录名。
- 建议标题、标签、摘要、置信度与简短理由。
- 最多 5 个精确重复或相似项。
- 规则冲突、标题语义和页面信息提示。

以下任一事实触发审批：新目录、多级目录、目标不明确、非高置信度、精确重复、相似项、规则冲突、标题变化过大、特殊文件夹、页面信息不足或状态过期。

用户可设置 AI 单次最多连续补建 1–5 级目录，关闭新目录时有效上限为 0。方案会保存生成时的层级上限，风险判断和本地执行都再次校验，不能只依赖模型遵守提示词。任何新目录创建仍需审批；超过上限的模型结果会在本地截断并提示。

用户还可设置 1–5 级的推荐目录深度，不计算“书签栏”根目录。该偏好同时进入模型上下文，并对本地已有目录候选做轻量排序；明确规则、历史偏好和当前目录仍有更高优先级。

## 路由与界面

```text
安全方案 -> 本地执行 -> 网页结果提示 + Popup 最近结果

风险方案 -> 暂存到待整理箱 -> 网页审批浮层
                                | 允许 -> 本地执行
                                | 拒绝 -> 保留暂存书签
                                | 调整 -> Side Panel 对话
```

网页浮层只由收藏事件触发，关闭后页面不保留可操作入口。Popup 是队列总览；Side Panel 是单个会话的工作区。Side Panel 不可用时回退到扩展标签页。

## 重复与撤销

- 精确 URL 重复：审批后把方案应用到既有书签，再删除临时副本。
- 相似收藏：只展示相关项，不自动合并。
- 拒绝：不删除暂存书签。
- 撤销：按 `batchIndex` 逆序恢复，且每一步再次检查当前状态。

## 对话与学习

自动执行后再次对话时，重新读取书签当前标题、父目录和索引作为基线。调整只替换当前方案，用户仍需允许后才写入。

“以后/今后/下次……都/总是/一律……放/收藏/归类到……”被识别为未来意图，批准后保存为固定规则。固定规则包含域名、可选 URL/标题范围、偏好或避开目录及来源会话 ID，可在设置中删除。

解决会话时清空完整消息。未解决会话 7 天过期；网络失败最多重试两次。

## 模型协议与结构化契约

模型档案同时支持以下两种 OpenAI 兼容协议，由用户在设置中选择：

- `OpenAI Chat Completions`：请求 `${endpoint}/chat/completions`，使用 `response_format.json_schema`。
- `OpenAI Responses`：请求 `${endpoint}/responses`，使用 `text.format.json_schema`。

新建自定义档案默认选择 Chat Completions，不自动迁移或改写已有档案的协议。两种协议共享同一个分析契约、提示词和本地校验器，必须恰好返回 `folderPath`、`title`、`tags`、`summary`、`confidence`、`reason` 六个字段。

结构化输出采用双保险：适配器继续发送协议原生 JSON Schema，同时把完整字段、类型、枚举和长度约束写入系统提示词。这样既利用原生严格输出，也兼容接受 Schema 参数但不实际执行约束的中转服务。Provider Schema 与本地 Zod 约束从同一契约维护，避免出现模型满足请求 Schema、却被本地隐藏规则拒绝的差异。

连接测试必须使用代表性的六字段分析结果，不能再用单字段 `{"ok":true}` 推断复杂结构化输出能力。测试通过只代表当前档案、协议和模型组合能够产生完整分析结果；切换协议或模型后必须重新验证。

缺字段、多字段、错误类型或危险字段仍然失败关闭，不自动猜测或补全模型意图。失败消息使用中文指出字段级原因，但不记录或展示原始网页正文、API Key 或完整模型响应；书签继续遵守“先保存”不变量并保留原位等待重试。

## 模型上下文

- URL：移除用户名、密码、查询参数和片段。
- 描述：最多 500 字符。
- 正文：最多 6,000 字符，并先做敏感文本脱敏。
- 候选目录：最多 24 条发送给模型；先按规则、历史偏好、当前目录、内容相关性和推荐深度在本地排序。
- 相关项：最多 5 条，只含必要标题、脱敏 URL 和已有摘要。
- 对话：仅当前会话最近 10 条消息和本次指令。

模型档案可单独分配给 `agent`；未配置时回退到 `classify` 分配。模型必须已验证且具备分类能力。

## 验收重点

- 原生收藏在模型延迟或失败时仍立即存在。
- 无风险方案自动执行，风险原因逐项触发审批。
- 风险书签进入已配置待整理箱，允许/拒绝不丢书签。
- 网页浮层、Popup、Side Panel 对同一会话保持一致。
- 自动执行后仍能基于当前位置对话调整。
- 精确重复合并与整个操作批次可以撤销。
- 查询参数、超长正文、完整书签库和私密备注不进入模型请求。
- Chat Completions 与 Responses 均可由用户选择，并通过同一六字段真实探针。
- Provider 忽略原生 JSON Schema 时，模型仍能仅凭提示词返回完整合法方案。
- 不完整或包含未知字段的方案被拒绝，并显示不含敏感数据的中文字段原因。
